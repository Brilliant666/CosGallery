# 单张媒体与独立作品回收

PR #50 的实现候选。单张详情只回收当前媒体；图库账本的资源目录按独立作品整体回收。当前文档描述候选代码，不代表已部署或执行真实数据操作。

## 操作入口

| 位置 | 操作 | 结果 |
| --- | --- | --- |
| 图片/视频详情的红色垃圾桶 | 将当前媒体移入回收站 | 原件保留；从当前图集移除，返回图集；最后一个媒体需明确确认，随后返回博主页 |
| 图库账本 → 资源目录 → 作品行 | 将独立作品移入回收站 | 覆盖该 Work 的全部本地副本；退出正常图库与资源目录，原件及附件保留 |
| 回收站 → 单张媒体 | 恢复所选媒体 | 核对原件身份与所属作品，恢复成员顺序、封面和可见状态 |
| 回收站 → 独立作品 | 恢复整个作品 | 恢复回收前各副本和主副本状态；此前单独回收的媒体继续留在回收站 |
| 回收站 → 独立作品 | 永久删除 | 单独预览并确认全部副本的原件、附件和派生文件范围，完成后不能通过应用回收站恢复 |

资源目录的一行代表独立作品。即使作品有多份本地文件，也只需对这一行操作一次。确认框展示全部副本，不将整作品操作缩成只删除当前主副本。当前不提供批量作品删除或自动判重。

单张回收不会触发整作品删除。媒体剩余两项变一项时保持合法展示结构，最后一项回收后不留下活动空图集。正常文件仍保留在磁盘，所以回收不等同于释放空间。

## 确认与关联范围

资源目录是版本化读取结果，不是实时磁盘清单。整作品操作先取得独立预览，核对稳定 Work 身份、全部 LocalWork/Post、媒体和附件、文件身份、相关任务与共享路径；确认后再次复核。目录 NO 可能重排，不作为操作身份。

预览将确认范围保存在操作账本，不回收文件、不改作品状态。预览过期、文件新增或替换、成员和引用变化时必须重新取得预览。执行请求使用同一操作 ID 保证幂等。

- Work、LocalWork 及原来源/入库历史保留必要身份，正常资源目录和本地可用统计排除回收或已删除作品。
- 全部副本一同回收和恢复，原主副本关系保持；不需要在删除时逐个选择替代主副本。
- 回收使本地满足状态失效；整体恢复恢复由此次回收暂时失效的状态，原有来源和本地版本契约继续校验。
- 单张人工调整保留原接受版本快照，并追加 before/after 审计链。只继承调整前仍有效的接受决定；来源声明或原内容已经变化时不会顺带批准。删除广告不能仅因数量减少就自动重新下载。
- 旧入库计划、下载重试、身份注册和扫描识别作品回收标记，不自动重新接纳。单张回收也有持久成员记录，扫描不会把仍在磁盘上的广告重新加回图集。
- 单张恢复核对回收时文件身份；原件缺失、被替换或路径包含链接时保留回收记录并说明阻断原因。
- 整作品回收后，普通原件、缩略图和预览读取不继续提供该作品；回收管理接口要求管理员权限。

整作品恢复不会恢复此前单独回收的媒体。所属作品仍在回收站时，单张恢复不能绕过整体状态。永久删除覆盖这些已单独回收的媒体，因此确认范围包含它们。

## 永久删除与失败恢复

永久删除只从独立作品回收记录发起，不在单张详情或普通资源目录提供直接永久删除。

1. 核对确认清单、管理员权限、活动任务和跨进程操作占用。
2. 固定每个文件的身份，写入私有操作日志；按各存储根把原件、附件、派生文件移入内部隔离区。
3. 在数据库事务内再次检查作品、文件索引、共享引用和任务状态，解除当前媒体索引关系、记录作品已删除，并保存操作提交状态。
4. 提交后清除隔离文件，仅清理所选副本内已为空的目录；保留博主目录和清单外文件。
5. 只有确认清理完成才报告永久删除完成。数据库已提交但文件尚未清完时显示待清理；未提交且恢复未完成时显示待恢复。

执行中断由操作账本判定提交阶段，不再仅凭 Post 是否存在。提交前还原隔离文件，遇到原位置被其他文件占用时保留恢复材料并报告冲突；提交后只重试已确认的清理。不用恢复旧整库撤销单个删除。

回收站保留未完成操作入口，可以按同一操作 ID 继续处理；不得把其他作品的待处理日志顺带作为本次用户操作执行。永久删除完成后的原件不能靠数据库恢复点找回；应用恢复点不包含媒体。

## 受控边界

以下情况显示阻断原因，不静默扩大范围或绕过外键：旧本地作品尚未可靠关联 Post、目录归属冲突、图库根外路径、符号链接或 junction、已登记副本路径重叠、共享媒体或派生文件、相关任务仍在执行，以及确认后发生的新变化。

当前单张入口只提供回收和恢复。永久删除后的作品身份和路径保留删除决定，不提供自动复活或绕过决定的重新入库按钮。纠正重复 Work 身份属于独立维护需求，普通回收不会自动合并其他作品。

旧回收记录仍可通过旧入口恢复，但不能绕过新的整作品或单媒体回收状态。存在持久作品关联或回收记录时，清空重建索引会被明确阻止；日常更新继续使用保留身份的重新扫描，避免破坏恢复关联。

## 技术入口与验证

- `media-trash-service.ts` 与 `media-trash-routes.ts`：单张回收、恢复、管理员回收预览及成员顺序。
- `work-removal-service.ts` 与 `work-removal-routes.ts`：整 Work 预览、回收、恢复、永久删除及操作回执。
- `permanent-deletion-service.ts`：固定文件身份、隔离、提交和恢复日志，兼容旧 Post 日志。
- `work-removal-guards.ts`：身份、入库、下载重入保护。
- 新迁移 `000028_work_removal.sql`：作品回收标记、路径、操作账本、单媒体回收与接受版本调整记录。

专项覆盖单张/整作品交叠、恢复顺序、最后媒体、扫描不复活、来源接受决定、全部副本和附件、过期预览、并发引用、故障恢复、权限以及普通媒体 URL。测试使用合成数据库、临时媒体及临时 HTTP 端口；候选通过测试不等于正式数据删除或部署。

旧 Folder DELETE 继续返回 410，原因和历史隔离复现见 [旧入口退役记录](legacy-folder-delete-retirement.md)。早期只读审查见 [审查记录](duplicate-album-removal-review.md)；其中入口描述属于 PR #50 修改前的基线。
