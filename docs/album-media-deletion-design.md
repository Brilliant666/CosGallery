# 图集与媒体删除方案

状态：设计提案，尚未实现或部署。2026-09-29，基于 `900c1d828c3457124a9a5c7496593ab3781107e6` 源码只读审查。此前的实际操作见 [现状审查](duplicate-album-removal-review.md)。本文件不授权执行真实数据删除。

## 1. 为什么旧文件夹删除退役

旧 `DELETE /api/folders/:slug` 按物理 Folder 删除，不能表达规范博主、Work 和多个本地副本的关系。它先删原件及派生文件，再清除扫描状态和数据库记录。遇到 LocalWork 对 Post 的外键引用时，数据库删除会失败，但已删除文件不能随 SQL 回滚。

[PR41 的退役记录](legacy-folder-delete-retirement.md) 保存了旧版本隔离复现：有引用的样本出现文件已删而记录仍在；`deleteSourceFolder=true` 还会覆盖整个目录子树和附件。那是历史合成测试证据，不是本轮执行结果，也不代表正式库已发生同类损坏。旧菜单所在页面当时已不在正常路由中，因此关闭旧 API 并返回 410，阻止继续使用该不完整路径。该治理没有交付新的完整图集删除流程。

## 2. 用户操作对象

| 所在页面 | 默认垃圾桶操作 | 永久删除入口 | 成功后 |
| --- | --- | --- | --- |
| 某张图片/视频详情 | 仅将当前媒体移入应用回收站 | 明确标注“永久删除这张图片/这个视频” | 显示下一项；无下一项则显示上一项 |
| 图集详情或博主作品卡片菜单 | 将所选图集的当前本地副本移入应用回收站 | “永久删除此图集的本地文件” | 返回或刷新所属博主作品列表 |
| 应用回收站 | 按单媒体/整图集显示项目及范围 | 对所选项目永久删除 | 更新回收站与关联列表 |

单张详情不能继续绑定整 Post 删除。整图集操作在图集层提供独立入口。视频沿用同样范围规则。图集含多份本地副本时，确认页显示本次是哪一份、还有几份；本期默认只处理所选副本，不暗中包含其他副本。

媒体详情已有 `activeMediaItem.imageId` 可识别当前项，执行须同时携带所属 Post 并校验归属。成功后清除已删除的 URL media 参数，并用服务端结果更新当前项、图集和全局数量；不能复用按 Post 移除的 store 方法将整个图集删掉，也不能固定将全局统计减一。

删除最后一个媒体会让当前副本没有可展示内容，必须重新呈现这一结果并确认，不能沿用普通单图确认直接扩大范围。该特殊确认仍只处置当前媒体和必要的副本状态，不自动包含其他附件或副本。整套文件清理须另用图集操作。

确认页显示博主、图集标题、当前媒体缩略图/文件名或整套清单摘要、媒体和附件数量、预计处置字节、已缺失文件、实际处置方式，以及主副本/来源满足状态的影响。实际范围由服务端生成，不能用分页或筛选后的可见数量替代；预计处置字节不冒充操作系统实际释放空间。内部数据库 ID 不作为用户必须输入的操作条件。

“移入应用回收站”可恢复且保留磁盘原件；“永久删除”明确说明清除所选原件和派生文件、完成后无法由应用回收站恢复。两种动作独立呈现，不再用含糊复选框切换。Windows 回收站、故障恢复隔离区和应用回收站使用各自准确名称。

## 3. 预览与执行契约

所有新入口与旧删除调用者统一经过预览/执行服务。旧 Post/Images 别名不能留下可绕过图集身份核验的永久删除路径；不兼容旧调用返回明确错误，不重新开放 Folder DELETE。

1. **只读预览：** 验证管理员权限、目标媒体确属当前图集和博主，解析 Work/LocalWork/Post/Image 关系。列出直接引用、历史软引用、主副本、来源满足、下载/接纳/扫描活动以及路径重叠或共享文件。只核对所选范围，不自动扫描全库。
2. **确定文件范围：** 单媒体包括对应原件与派生；整图集逐项列出目标副本的媒体和附件。目录中出现未确认文件、嵌套作品、其他副本或共享路径时，拒绝扩大范围，要求重新预览。只删除确认清单中的文件，最后仅清理确认边界内已为空的目录。
3. **形成确认快照：** 服务端保存/签发绑定目标、动作、文件身份、引用版本、主副本决定及有效期的确认凭据。预览本身不保留写锁、不生成备份、不移动文件。
4. **提交执行：** 携带确认凭据和幂等请求键；相同请求返回同一操作状态。执行时重新核验权限与快照，任何范围变化均要求重新预览。UI 禁止重复提交，但正确性由服务端保证。
5. **互斥：** 在文件操作前取得与扫描、接纳及媒体写入共同遵守的持久操作占用，并复核短事务内的关系。优先接入已有 `local-admission-lock.ts` 协议，核对与 maintenance 锁的全局获取顺序，避免删除与入库/扫描互相等待。现有进程内 maintenance 锁可保留，但不能独立承担跨进程保护；过期时间不能证明旧进程已停止。

图库不可用、数据库处于内存回退、相关任务仍在执行、引用无法归属、共享原件或路径身份变化时，返回具体阻断原因。符号链接/junction、路径越界、文件替换及派生生成并发沿用并扩展现有保护。不能通过关闭外键、随意置空引用或先删原件来绕过阻断。

## 4. 媒体、作品和历史如何处理

| 对象 | 处置规则 |
| --- | --- |
| 所选原件与派生 | 回收保持原件；永久删除按确认清单隔离后清除，记录每项结果 |
| 图集内剩余媒体 | 原顺序保留；代表图被删时选择剩余首项，更新封面/头像引用、数量及缓存 |
| Post 和 Image 索引 | 区分人工回收、永久删除、扫描发现缺失；保留必要删除标记和关联审计，不以清空引用代替领域处置 |
| 所选 LocalWork | 单媒体变更记录内容已变化；整份删除或最后媒体删除后明确不可用，保留 ID 与来源/接纳历史 |
| Work 身份 | 保留独立作品身份及历史；最后副本删除后成为无可用本地副本，不显示为普通可浏览图集 |
| 主副本 | 删除当前主副本且仍有其他有效副本时，预览要求用户选择后继副本，或明确选择暂不展示；决定与删除同事务记录，相关排序确认按原契约失效或重新确认 |
| 来源绑定与本地满足 | 作品身份绑定保持；受影响的本地满足记录标为失效或待复核，不能仍宣称删掉的副本满足来源；有其他副本时也按既有契约核验 |
| 入库计划、任务与人工决定 | 保存原事实，不重写已执行计划为未执行；新增删除决定引用旧记录；不自动重新入库或下载 |
| 喜欢、收藏、目录和 Companion | 明确现存收藏不可用状态，过滤已删除内容，并使派生统计/目录版本失效；共享只读接口同步遵守可用性 |

单媒体处置必须满足现有索引不变量：活动 Post 有 `position=1`，成员顺序连续，`single` 只有一个成员，`carousel` 至少两个。两项变一项需兼容转换展示类型及原目录角色，不能改变作品身份、标题或将 owned 目录错误变成普通博主目录。零项不能留下活动空 Post。回收记录另存原归属和顺序，恢复时重新核验并恢复合法结构，不依赖已重排的位置猜测原关系。

单项回收和整图集回收需要分别记录操作范围；整图集恢复不能顺便恢复此前单独回收的媒体。重复点击不制造重复记录。父图集已永久删除时，不允许单媒体恢复偷偷复活整个图集。

采用持久的“人工删除”决定/标记阻止扫描、重建和旧计划重试将其当成暂时丢失的文件自动恢复。标记绑定本地副本与文件身份，不能仅按路径永久屏蔽后来不同的内容；重新出现的文件需要明确恢复或新的接纳决定。查询、扫描和兼容迁移都要识别该生命周期，不能只新增一个前端隐藏字段。

**重复 Work 身份纠正另设显式动作。** 删除本地文件不隐含合并两个 Work。如确有重复身份，应预览保留作品、冲突关系和引用迁移，再记录退役/合并决定并保留可追溯 ID。不得按标题或数量自动选择保留项，也不在普通图集删除中硬删整条历史链。

## 5. 永久删除执行与故障恢复

复用现有文件身份核验、私有隔离区和日志机制，但扩展为操作级状态机。当前代码按“Post 是否存在”判断提交与否；单媒体删除和保留身份标记后该判断不再成立，必须升级恢复判据并兼容旧日志。

推荐流程：

`已确认 → 已占用并复核 → 文件隔离中 → 文件隔离完成 → 数据库已提交 → 清理中 → 完成`

- **文件隔离前**：持久保存操作 ID、精确清单、文件身份、引用快照、恢复位置及预期数据变更；日志不可存于可公开读取的位置。需要恢复材料时先核对已有材料是否适用，不能每删一张自动复制全库。
- **文件隔离**：原件和各类派生分别进入所在卷的私有隔离区，逐项持久记录，不假设跨卷 rename 可用。任一失败停止后续处理并尝试还原已移动文件。
- **数据库提交**：短写事务中再次核对占用、引用和版本，写入媒体/副本状态、主副本决定、来源满足失效及目录版本，并同事务记下操作已提交。事务失败时从隔离区还原文件。
- **不可逆清除**：仅在确认数据库已提交之后清除本操作隔离文件。未完成全部清除时显示“图库已移除，磁盘清理待完成”，不能报告已彻底删除或已释放全部空间。
- **完成**：所有确认文件均已清除或预览中已记录缺失，必要派生状态已更新；保留轻量审计回执。清理失败可按同一操作重试，不重放删除业务决定。

恢复表：

| 中断位置 | 重新核对后的行为 |
| --- | --- |
| 数据库尚未提交 | 依操作日志还原已隔离文件；原位置被新文件占用时保留隔离材料并报告冲突，不覆盖 |
| 数据库已提交、文件清理未完成 | 延续已授权清理；不因客户端超时重复创建删除，不以恢复旧整库来撤销 |
| 数据库提交结果暂时无法判断 | 暂停不可逆清除，保留材料并显示待恢复，不能凭异常字符串推定失败或成功 |
| 日志损坏、文件身份或根配置变化 | 停止该操作并提供明确恢复状态，禁止猜路径或批量清空隔离区 |

永久清除完成后，应用回收站不能恢复原件；应用恢复点仅包含数据库/配置，不能当作媒体备份。若用户需要日后找回原件，应使用可恢复回收模式或已有独立媒体备份。故障隔离保护执行一致性，不承诺对永久删除提供撤销能力。

## 6. 验收与实施顺序

1. 实现统一目标/预览/生命周期及旧入口兼容保护，使用合成数据库和临时媒体。
2. 实现单媒体与整副本的回收/恢复、关联处理和持久执行记录；将永久删除接入同一范围契约及新版故障恢复。
3. 接入详情页与图集页的独立入口、中文范围确认、操作状态和正确返回行为。
4. 通过下面的专项与候选完整 CI，完成隔离交互验收后再进入正式部署流程；真实删除仍由用户对具体对象确认。

必要验收覆盖：

- 删除当前单图只影响该媒体；图集筛选、翻页、切图及预览后切换目标不会错删；viewer/匿名无删除权限。
- 删除首项/中间项/最后项、两项变一项、最后媒体确认、封面/头像更新、owned 目录、图片/视频混合及单项/整套恢复交叠。
- 同一 Work 多副本、删除主副本并指定后继、最后副本、来源满足与历史引用、重复 Work 未自动合并。
- 文件预览后变化、新附件、共享路径、缺失文件、越界和 junction、扫描/接纳/派生生成并发、跨进程互斥与幂等重试。
- 文件移动、日志持久化、数据库提交、清理各阶段的失败/崩溃恢复；恢复目标占用；旧日志升级；提交结果未知时不清除。
- 扫描/重建不复活人工删除，明确重新接纳可区分同路径新内容；目录、Companion、收藏与其他读取入口不泄露已删除内容。
- 迁移完整性、外键和代表项约束；未选中作品、文件、用户配置及恢复材料保持。

本轮只完成方案和源码核对，未执行以上验收、产品改动或任何真实处置。
