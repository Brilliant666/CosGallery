# 作品标题与来源适配边界

图库的 Work 是作品身份，LocalWork 是本地副本，SourceWork 是外部来源条目。来源标题和编号提供证据，不直接定义图库作品身份。没有来源资料也可以通过本地接纳创建作品；正常绑定与本地满足记录不是应被删除的临时补丁。

## 共用解析结果

各入口通过 `parseWorkTitle(raw, creatorNames)` 获得同一份结果：

| 字段 | 用途与边界 |
| --- | --- |
| `raw` | 原始输入，保留原文，不用规范化结果覆盖证据。 |
| `displayTitle` | 规范化 Unicode 和空白，仅去除有边界的已知博主前缀、外层 NO/VOL 编号及明确媒体数量后缀。 |
| `exactKey` | 当前与 displayTitle 相同，保留大小写、标点、内部数字和主题修饰；只是保守比较依据，不是永久作品 ID。 |
| `candidateKey` | 放宽裸编号、已知名称排版、标点和大小写，仅用于提示待核对候选，不能据此绑定、复用或标记来源满足。 |

`extractWorkDisplayTitle`、`normalizeWorkTitle`、`workTitleCandidateKey` 为兼容入口，均读取以上结果。普通本地接纳与本地优先来源复用不再各自生成不同的同名解析字段。`isWorkTitleCandidate` 仍保留既有保守的副标题候选规则，候选比较不具有身份授权。

相同 exactKey 也需要限定已确认的规范博主、检查唯一性、冲突、本地副本和版本接受等既有条件。未知名称不会被学成别名。来源 NO/VOL 属于来源顺序，不能凭数字相同认定同套；作品内部的主题编号仍有意义。

例如 `1 - [Studio] Summer` 与 `[Studio] Summer` 可进入候选核对，但 exactKey 不同，不得静默复用。`Theme 2` 与 `Theme 3` 的内容数字不能抹掉。

## 来源适配器

`parseCostuanVerificationTitle` 返回共用解析字段，并另外提供明确命名的 `verificationKey`。该字段保留 Costuan 已有字形／错字处理、来源编号和包含关系兼容；`normalizeCostuanTitle` 与 `areCostuanTitlesCompatible` 是其既有来源核验入口。它们可用于已明确来源范围中的目录／文件核验，以及提示“来源特有变体，需人工核对”；不得用来给本地目录分配 Work 身份。后者只暂停重复获取，不意味着兼容文本已经证明同套。

例如来源适配器允许“黑咝自怕”和“黑丝自拍”在来源核验中兼容，但共用 exactKey 仍不同。不能把来源平台的错字规则推广为全图库身份规则。

历史本地对账应先使用明确身份记录；没有明确身份时，只能使用同一博主范围内唯一、非空的共用 exactKey，并继续执行既有冲突保护。candidateKey 或来源 verificationKey 只能提供人工核对证据，不得回退为自动分配 Work。

旧目录对账遇到格式候选、编号与标题冲突或多个精确身份时，保留 `ambiguous` 与空 Work 关联，并在该本地观察记录的 `provenance_json.sourceTitleReview` 留存候选 Work ID。它只是待核对证据，不是绑定、接受或满足决定。共用 `acquisitionHeldSql` 据此暂停相关来源的新任务规划、领取及既有执行前检查；已存在任务不被伪装成成功。依据仅对同博主、仍活动且未解决的本地行有效，重新核对确定身份或该目录不再活动后自动不适用，其他人工／撤销持有规则仍保留。

缺少本地覆盖与“允许重新获取”仍是两个概念：旧报表的 missing 数量表示没有已确认覆盖，不保证可以自动下载；待核对行和任务的 `review_required` 状态提供对应说明。

历史编号重建服务也使用相同 exactKey 校验本地关联；编号重建职责不变，但来源字形或包含兼容只能产生 unresolved/titleConflict。存在这些阻断时 apply 不写入；计划里的待核对候选也不会同时列入新下载任务。已明确的旧关系仍按原规则保留，不因更严格的候选解析批量拆除。

## 数据保护

本解析契约不回写历史标题，不重建 Work，不删除人工绑定，不重算来源满足，也不自动执行历史计划。历史数据纠正必须另有明确依据与授权。范围标题解析与范围审核授权是另一层能力；解析出多个编号不等于确认对应多个独立作品。
