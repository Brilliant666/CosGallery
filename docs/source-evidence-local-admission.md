# 来源资料、批次出处与精确对应

CosGallery 的主数据是规范博主、Work、本地副本与媒体。外部来源用于记录资源出处、发现和补缺，不要求所有本地图集先转成 Costuan 目录。

**不规范原文可以先保存；保存不等于核验成功，更不等于创建作品、规划下载或完成入库。**

## 从哪里操作

在**图库账本 → 博主库 → 管理资料 → 来源与补齐**中打开**来源资料 · 原文留存与本地接纳**；默认“概览”只读查看，不发起检查任务：

1. **手工登记来源资料**：填写真实平台标识、页面链接、原标题和原始目录文本。目录可以不完整或为空，范围条目与未知文本会保留，不要求逐行补姓名或伪造编号。
2. 查看资料的归属、完整性、诊断和原文。原文按纯文本显示，不执行 HTML，也不自动访问链接。
3. **归属待确认**时核对具体页面和博主，填写依据后确认该观察。确认只作用于该页证据，不创建全局别名。
4. **身份冲突**时保留资料，不能在这里强制改绑或据此接纳。
5. 归属已确认后点击**准备本地接纳**，进入带入规范博主及资料的网页入口，再选择已解压作品并确认。正常入库不需下载 JSON 或使用 CLI。

Costuan、ecytt、sndiary 等可按真实出处手工登记。没有专用站点适配器的平台不会因此获得自动采集能力；未知目录仍需人工判断。

## 四种信息不要混为一谈

| 信息 | 证明什么 | 不证明什么 |
| --- | --- | --- |
| 来源资料 / 观察 | 曾获得这段页面原文、标题和诊断 | 完整目录核验、真实作品数量、文件获取成功 |
| 批次出处 | 某本地 Work / 副本来自这份资料 | 精确外部条目等同、逐字节相同、本地满足 |
| 精确条目对应 | 某个明确条目与已有 Work 的对应依据 | 自动接受版本、核销任务、整份合集均满足 |
| 本地满足 / 版本接受 | 在可靠映射及当前本地有效性下，明确决定不再获取某来源 | 保存原文即可满足、任何同名作品都等同 |

普通本地入库无需来源。带入资料只增加批次出处，不改写已有 Work 身份、原接纳计划或历史 `staged` 回执。后补可靠来源可复用已经接纳的本地版本，具体语义见[本地优先与来源复用](local-first-source-reuse.md)。

来源 NO 是某个来源的编号，不是 CosGallery Work ID，也不是[自有目录 NO](own-resource-catalog.md)。范围内的多个编号不自动展开为多个文件名或作品。

## 后补已有作品：当前仍需稳定 ID

资料详情已经提供网页表单，但**以下事后维护并未做成全部图形化身份选择**：

- **后补已有作品批次来源**：填写已有 Work ID、可选 LocalWork ID 和依据，确认后只保存出处，不移动文件或申请精确满足。
- **精确条目对应**：选择具体解析条目，填写已有 Work ID、可选 SourceWork ID 及依据。SourceWork ID 与 Work ID 不是同一编号。
- 所选身份必须属于当前博主；已有 SourceWork 还须与 Work 和来源页面一致。冲突会拒绝，不提供通用 Work 合并。
- 一个范围可分别关联多套实际 Work，每条对应独立保存；不能据此宣称整个范围已满足。

这些表单不属于每次普通入库的必经步骤。来源资料中的“高级维护：下载 CLI 预览 scope”也只是既有维护入口：下载 scope 不执行接纳；维护命令见[本地目录接纳](local-folder-admission.md)。

## 配套插件 0.11.9

[CostuanArchiveManager 安装与连接说明](https://github.com/Brilliant666/Script/tree/main/CostuanArchiveManager)以 Script 仓库为准；[0.11.9 资料交接说明](https://github.com/Brilliant666/Script/blob/main/CostuanArchiveManager/docs/source-evidence-handoff.md)列出协议与隔离验证。

服务端声明 `sourceEvidenceV1` 时，插件可在严格目录预检未通过的受支持分支，将已观察到的原文独立留存：

- 只保存实际取得的页面资料，不猜作品、文件名或缺失资源，不继续访问网盘来补证据。
- 资料留存与原完整来源导入 / 精确暂存分离。正常严格成功路径仍走原流程；部分资料不会替换原完整来源快照。
- 回执未知时保留同一请求，**重传资料（不恢复任务）**仅重传原内容，不重新领取、采集或自动恢复暂停队列。
- 身份、当前 worker、attempt、轮次与权限仍须通过；旧服务没有能力时保留原错误，不伪报保存成功。
- 源码更新不会自动安装或重载用户浏览器中的插件。安装 / 重载后需自行核对扩展版本和连接状态，历史任务仍保持原状。

浏览器实际使用版本取决于用户加载目录及重载状态，不能仅凭服务器支持就称插件已升级。此指南也不授权恢复任何历史来源检查或暂存任务。

## 数据保留、安全与失效

同一个请求键重传返回同一观察，换内容不能冒充原重传。新观察不会改写旧原文；归属确认带代次检查，晚到的旧确认不能覆盖新判断。

资料中不要填写 Cookie、登录令牌、提取码或密码。普通原文 / 入口与受保护的分享凭据分开；手工输入和服务端均有凭据防护，不能把资料区当密钥保险箱。

服务结构由迁移 `000024_source_evidence.sql` 建立：

| 表 | 职责 |
| --- | --- |
| `source_evidence_pages` | 平台 / 页面身份及归属代次 |
| `source_evidence_observations` | 不可变原文、解析结果、请求键与摘要 |
| `source_evidence_identity_decisions` | 具体观察的人工归属依据 |
| `source_evidence_admission_links` | 批次出处或精确条目与既有 Work / 副本的关联 |

资料读取按博主、观察和关联索引进行，不重新生成全库资源目录。原 Work、SourceWork、LocalWork、下载任务和接纳计划仍是各自权威记录。

接纳已索引但出处关联失败时，同一计划保留索引检查点，可继续关联而不重复移动或新建 Work。目标占用、文件变化、身份冲突与活动 claim 仍阻止执行。精确恢复见[网页审核](local-admission-web.md)。

## 历史：来源资料隔离规模与查询计时

使用已有一致性备份的独立副本，先在副本应用 000024：601 位博主、7,250 Work、7,247 LocalWork、357,144 媒体、4,776 SourceWork、3,053 下载任务。本次合成观察每份 120 行/3,851 字符，样本博主有 7 份观察；不读取或扫描真实媒体。

同一 Node 24.19.0，预热一次、测五次；下表为 **服务调用耗时，不是 HTTP 或页面耗时**：

| 调用 | 中位数 ms | 范围 ms |
| --- | ---: | ---: |
| 保存观察 | 3.178 | 3.075–3.752 |
| 同请求重传 | 0.410 | 0.318–0.497 |
| 按博主读取资料 | 1.565 | 1.302–1.940 |
| 观察详情 | 0.161 | 0.158–0.172 |
| 接纳来源引用核对 | 0.315 | 0.298–0.663 |

实际 EXPLAIN：博主读取命中 `idx_source_evidence_creator`，观察/页面详情命中各自整数主键，关联命中 `idx_source_evidence_link_observation`。操作前后主业务表数量和完整目录生成状态相同，没有目录失效/重建。不是满 20 份超大原文的压力测试，也不承诺所有输入都具有相同时延。
