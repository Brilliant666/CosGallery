# 来源资料与本地接纳（Draft）

这条路径保存不完整的来源资料，不把它伪装成完整来源导入。
规范博主、Work、LocalWork 和现有媒体身份仍是主数据。

## 复用与边界

- 原 `ArchiveCatalogService` 的完整目录、文件选择和原分享验证保持；只有通过它的旧路径才可继续精确自动补缺。
- `SourceEvidenceService` 独立保存页面观察、原文、解析疑点和页面级归属判断。保存观察不创建 Work、SourceWork 或下载任务。
- 原 `LocalFolderAdmissionService` 继续处理明确的已解压目录、原名/内部结构、同卷移动、定向索引及中断恢复。
- 批次来源仅说明文件来自哪份观察；已有精确来源仍用原 Work 身份与版本接受服务处理。批次来源不是作品等同、文件逐字节相等或本地满足证明。

## 本地目录交接

在博主库的资料对话框展开“来源资料”，保存手工资料或查看插件失败路径留下的资料。页面身份尚未确认时，先核对具体页面归属；确认不会把页面标题注册成全局别名。

选择一份已确认归属的资料，填写本地等待区及一级作品目录名，下载 **preview scope**。这是选择范围，不是执行计划。平台、博主和资料 ID 会随范围传递；不要求每套手写 JSON。

```text
local-folder-admission preview <absolute-scope.json>
```

新增可选范围字段：`sourceEvidenceId`、`acceptExistingVersion`。
输出仍为 `confirmed:false`；普通本地接纳保持 `localOnly:false`。预览的来源候选仍需核对，不能因标题相似把它当成新作品或已确认映射。已有可靠 SourceWork 应选择 `identity.kind=existing`，复用该来源真正指向的 Work。

确认具体作品、目录和版本接受范围后，才使用原 `apply`；同一不可变计划的中断继续使用 `resume`。本轮预览示例只使用合成目录。

`sourceEvidenceId` 可选且无默认写回值：旧计划保持原 payload/hash；不能向已执行计划添加字段后重放。后补批次来源使用独立关联：

```json
{
  "kind": "link-evidence",
  "confirmed": true,
  "observationId": 1,
  "creatorId": 1,
  "workId": 1,
  "localWorkId": 1,
  "key": "explicit-provenance-decision-key",
  "reason": "用户确认这份本地副本来自该页面，尚未确认具体外部条目"
}
```

通过原 `local-folder-admission decide <absolute-decision.json>` 调用。示例 ID 不是生产 ID；不执行文件移动，不改写旧接纳计划，不自动满足任务。

## 失败与恢复

文件移动与数据库不是同一个原子事务。接纳已经索引但批次关联失败时，该项保留 `indexed` checkpoint 和错误，同一计划可重试关联而不重复移动或建 Work。此前已完成的项不重置。目标占用、manifest 改变、身份冲突及活动任务保护仍按原服务处理。

部分观察保留历史，不刷新/删停旧的完整 SourceWork；范围条目保留端点，不展开猜测文件名或获取任务。确认一个范围中的某套对应关系也不代表整个范围已满足。

## 持久结构与身份判断

增量迁移 `000024_source_evidence.sql` 新增四张表，fresh schema 同步：

| 表 | 职责 |
| --- | --- |
| `source_evidence_pages` | 平台/页面唯一标识、当前页面归属和判断代次 |
| `source_evidence_observations` | 不可变观察、原文、独立解析结果、请求键及 payload 摘要 |
| `source_evidence_identity_decisions` | 具体页面/观察的人工归属依据和预期代次 |
| `source_evidence_admission_links` | `batch` 批次去向或 `exact` 条目对应，关联既有 Work/LocalWork；必要时关联既有 SourceWork/身份决定 |

原 Work、SourceWork、LocalWork、下载任务和接纳计划均未替换。观察读取使用博主、观察和关联索引，不调用全库目录生成器或缺失计算。只有真正通过已有身份服务建立来源对应时，才沿用其受影响目录更新机制。

页面归属与目录解析分开：已有可靠页面绑定或规范名/已登记别名加本篇标签证据可以确认归属。标题、标签、条目前缀指向其他博主或已有页面归属冲突时保留冲突资料，不能仅凭客户端 creatorId 自动绑定。人工确认作用于具体观察，带代次检查，不创建全局别名。

同一请求键重传返回同一观察；换 payload 不得冒充重传。新观察不回写旧原文。页面身份新代次不会被晚到的旧确认覆盖。单套已对应另一个 Work、已有 SourceWork 的 Work 冲突仍被拒绝；不提供通用合并。范围可明确关联多套实际 Work，但每条对应单独保存，不代表范围全部满足。

其他平台只存其真实平台名和页面，不套用 Costuan 编号解析。没有站点解析器时原文列为待判断，仍可确认页面、记录批次和接纳明确的本地分套目录。

## 插件交接与安全边界

桥接能力协商新增 `sourceEvidenceV1`，独立资料接口继续校验任务、当前 worker、attempt、轮次和规范博主。资料保存不会自行完成/释放任务，也不返回猜测文件名。插件仅在旧的严格预检失败等资料留存分支调用；严格成功仍走原流程。

回执未知时保留原请求供显式重传；重传不恢复暂停队列。旧服务没有该能力时保留旧错误，不伪报成功。部分观察不覆盖扩展已有的完整来源快照。配套 Script Draft 不修改百度点击、选择或保存算法，也不更新正式扩展加载目录。

管理接口沿用管理权限和写入 intent 校验。原文以纯文本显示，不执行 HTML，不自动访问链接；浏览器手工录入在临时重传存储前拒绝明显会话凭据，服务端再次脱敏。分享 URL 的敏感参数和密码不进入普通资料；本功能不是新的密钥保险箱。原目录文本上限 200,000 字符/5,000 行、资源入口最多 20 项；仅新资料接口允许 1 MiB JSON，旧接口限制不扩张。

## 第一轮隔离验证

本轮只做 Draft 受影响验收，不将其描述成生产接纳或用户已收尾。

| 场景 | 本轮证据 |
| --- | --- |
| 无逐行姓名前缀、普通/范围/未知/缺数量混合 | 实际服务测试与浏览器；原文保留，范围不展开，冲突独立显示 |
| 无清单页面接纳两套 | 临时真实 JPEG/附件，经原 preview/apply/scanner；两套实际 Work、可查询批次去向，没有假下载/解压历史 |
| 本地先有、来源先有 | 真实服务集成；后补来源不改旧计划/媒体 ID，已有来源复用正确 Work，冲突拒绝 |
| 部分新观察 | 旧完整来源、既有本地满足及 staged 历史保留 |
| 重试/中断 | 丢失保存回执后刷新重传；第二套索引后关联失败再 resume；没有重复观察、移动、身份或满足 |
| 旧入口 | 接纳、身份、版本接受、博主优先来源路由专项；四工作区及合成图集 Viewer 浏览器冒烟 |
| 页面 | 管理对话框按博主懒加载；390px 窄屏、原文 HTML 惰性显示、明确归属确认、scope 下载和接纳去向读取 |

Node 24.19.0：服务端 11 文件共 147 个不同专项通过（其中来源服务 16 项在两轮中重复执行，不重复计数）；客户端 3 文件 46 项通过；双端类型检查与 production 构建通过。迁移相关覆盖 fresh、历史升级和重复运行。真实浏览器脚本阻断所有外网，仅访问隔离服务；图集正常媒体打开/切换/关闭没有额外详情请求。页面下载的 scope 再由编译后的真实 CLI `preview` 读取，仍为 `confirmed:false`。

配套插件使用真实 content/background 脚本夹具及独立 HTTP/SQLite 服务验证，记录在 Script Draft 文档。不是在真实分享或原扩展存储上试跑。收尾时仍需最终候选的本地全量、完整生产入口/Worker 启动矩阵与两端最终兼容验证；本轮 CI 按现有 Verify 正常运行。

## 规模与查询计时

使用已有一致性备份的独立副本，先在副本应用 000024：601 位博主、7,250 Work、7,247 LocalWork、357,144 媒体、4,776 SourceWork、3,053 下载任务。本次合成观察每份 120 行/3,851 字符，样本博主有 7 份观察；不读取或扫描真实媒体。

同一 Node 24.19.0，预热一次、测五次；下表为 **服务调用耗时，不是 HTTP 或页面耗时**：

| 调用 | 中位数 ms | 范围 ms |
| --- | ---: | ---: |
| 保存观察 | 3.178 | 3.075–3.752 |
| 同请求重传 | 0.410 | 0.318–0.497 |
| 按博主读取资料 | 1.565 | 1.302–1.940 |
| 观察详情 | 0.161 | 0.158–0.172 |
| 接纳来源引用核对 | 0.315 | 0.298–0.663 |

实际 EXPLAIN：博主读取命中 `idx_source_evidence_creator`，观察/页面详情命中各自整数主键，关联命中 `idx_source_evidence_link_observation`。操作前后主业务表数量和完整目录生成状态相同，没有目录失效/重建。不是满 20 份超大原文的压力测试，也不承诺所有输入都具有相同时延。
