# 运行时与仓库治理

本文维护 CosGallery 的长期运行、验证和交付约定。具体任务按影响范围读取相关章节，不改变普通网页入库流程，也不授权重放真实任务。

## 运行时和构建身份

- 推荐官方 Node 24.21.0；`.node-version` / `.nvmrc` 固定该开发版本。
- 支持 Node `>=22.16.0 <23 || >=24.0.0 <25`，pnpm 10.28.0。Node 22 下限来自应用使用的 `node:sqlite` backup API；Verify 分别执行 Node 22、24 测试与双端构建。
- Windows 可解压官方 Node ZIP 到独立应用运行时目录，核对官方 SHA256 与签名后以绝对路径运行，不需要修改系统 PATH 或删除旧 Node。
- 服务端 `dist/build-info.json`、客户端 `dist/build-info.json` 在构建时记录版本、源提交、源树、dirty、构建时间和 Node；health 与侧栏版本提示读取产物身份，不在运行时读取 Git HEAD。非 Git 源码包明确显示未核实，dirty 构建不能当作干净候选。
- CLI、前端和后端仍须由同一已提交候选构建/运行。更新工作区提交并不能让旧进程自动重载。

## 最小检查与发行边界

`pnpm lint` 检查 manifest JSON、脚本语法及 diff 空白；`pnpm format:check` 只检查列明的新治理文件，`pnpm format:governance` 只格式化这些文件。不全仓库重排、不安装本机 hooks。

Dependabot 对 npm 每周、Actions 每月提出有限更新 PR，不自动合并。维护者和漏洞沟通见 [SECURITY.md](https://github.com/Brilliant666/CosGallery/blob/main/SECURITY.md)。GitHub main 规则属于远端管理设置，需先确认实际权限和用户选择，不以个人维护者无法满足的第二人审批作为默认条件。

原 GHCR tag 自动发布暂停。容器 workflow 仅支持手工构建检查，`push:false`、无 packages 写权限和登录；发行或部署容器需独立授权和验证。现存 Docker/compose 是上游遗留链路（包括上游镜像引用），**不作为已验收的 CosGallery 部署方式**。不应直接使用 compose 拉取上游镜像替代本项目候选。

## 分级验证与最小部署检查

以下规则适用于 CosGallery 的日常迭代，包括关联工作区中的开发和本机候选部署。按实际 diff 和影响范围选择验证，不将每次小修扩大为全项目审查或重新验收整套发布系统。

### 按影响选择检查

| 变更范围 | 默认必要检查 | 不默认追加 |
| --- | --- | --- |
| 普通 Markdown 文案、工作指引 | diff 空白、受影响链接/锚点及规则一致性；涉及文档站配置、组件或渲染疑点时再构建文档站 | 产品构建、前后端全量、部署及重启 |
| UI 文案、样式、布局 | 受影响页面检查；发布前所需前端构建；有行为变化才补相应测试 | 后端全量、插件或入库全流程验收 |
| 前端交互、播放选择 | 相关回归、类型检查、前端构建及受影响交互 | 无关页面、来源关系、恢复点矩阵 |
| 服务端接口、媒体处理 | 相关服务/接口回归、类型检查、服务端构建及必要隔离验证；跨前后端契约时覆盖两端 | 全库盘点、无关业务或发布系统重测 |
| 数据库结构、鉴权、文件移动、恢复机制、依赖/运行时或部署机制 | 按影响扩展集成、兼容或恢复验证；影响广泛时执行必要全量 | 重演真实业务、无依据扩大到其他模块 |
| PR 最终收尾 | 最终候选完整 CI，补齐受影响路径尚缺的验收 | 重跑仍适用的既有证据及所有历史矩阵 |

- 开始时简要说明改动范围和拟执行检查。同一轮相关小修先完成局部验证，形成可审查候选后再提交/推送；不要在每次编辑后等待一次全量 CI，也不跨越用户要求的交付节点无限攒改动。
- 同一代码及未受影响模块的证据可复用，注明对应 Head 和覆盖范围。旧结果不能冒充新 Head 重新全量通过；接口成功、DOM 测试和实际浏览器交互分别报告。
- 只有新改动、具体失败、相关依赖变化或尚未解决的疑点需要时，才扩大或重复检查，并说明依据。低影响可逆修改不新增仅复述实现的测试，不为通过而删断言、扩大 skip 或放宽业务规则。
- 浏览器或工具限制导致某项无法核实时，说明具体缺口，不绕过限制、不用其他层级证据冒充通过，也不自动扩展成无关的工具治理任务。

### CI 门槛与开发节奏

- 保留“最终候选精确 Head 的现有 Verify 成功后，才部署到真实 4141”的门槛。当前 Node 22/24 矩阵及检查内容不因本指引而减少；CI 的自动全量不等于要求本地再重复一遍全量。
- 同一 Head 已有适用的成功检查就复用；新 Head 按现有工作流等待对应检查。不以旧 Head 成功代替新候选检查，不临时跳过检查部署。
- 修改 CI 触发范围、检查内容或远端仓库规则属于另行明确授权的工作；不隐藏在普通修复或部署中。仅修改文档且未请求部署时，不为验证文档而切换服务。

### 4141 最小部署闭环

1. **准备与预检：** 确认部署授权、目标候选/CI和实际运行来源，核对业务空闲及相关自动化暂停状态；保护用户未提交/暂存修改、配置和密钥。确认所需前后端与 CLI 兼容配套、旧产物可恢复，以及已有恢复材料是否适用于当前变更。
2. **按需切换：** 优先复用已验证的构建产物和适用恢复点；不因每次小修自动新增备份。无适用恢复材料且本次切换确实需要时，再按现有恢复点服务创建。源码身份改变不等于进程已加载；应用代码/构建输入等价且无需切换时可复用进程，并如实记录。
3. **分阶段执行：** 确需启停时，分别调用“只读核对 → 精确停止 → 确认退出 → 启动 → 健康检查”。HTTP 检查不与启停放在同一请求；不沿用历史 PID，不停止身份不明或仍在执行业务写任务的进程。阶段失败不继续，也不拆分绕过工具拒绝。
4. **最小冒烟：** 核对实际运行版本、配套产物、Health/存储、必要的 operation/Worker 状态和本次受影响页面。正常启动自带的校验与迁移保护保留，不额外重复启动迁移或整套启动矩阵。HTTP 成功不能替代受影响交互的验证。
5. **简短记录：** 在既有本机忽略证据目录记录最终 Head、CI、复用/新增验证、是否实际重启及检查结果；只报告与本轮有关的数据变化和遗留缺口，不每轮生成一份全项目审计报告。

合并只改变 Squash 身份或文档时，比较运行候选与最终 main 的应用源码、锁文件、构建配置及配套产物。应用构建输入等价即可复用进程和产物，记录两者实际提交；不手改 build-info，不声称完整 Git 树相同或进程已经从新 SHA 重启。发现产品差异则按上述闭环更新，不能仅修改记录假装收口。

- 普通 UI 或局部非写入逻辑修改，不默认逐表统计正式库、计算整库哈希、盘点全库或重验所有插件接口。涉及持久化、迁移、文件操作、配置切换或具体数据疑点时，再选择对应的数据保护/比对；不能因此跳过本来必需的恢复保护。
- 优先复用已有部署工具及参数入口，不为每轮小修改复制新脚本或建设新发布体系。历史 `.mocks` 脚本可能绑定旧 Head、路径和业务断言，不能直接重放；确需调整时只针对本轮所需部分，不削弱源身份、文件范围或恢复安全检查，也不覆盖已留存的历史证据。
- 复用已有隔离环境，只验证受影响路径；未获授权不重跑真实入库、下载、回收、恢复或清理。正常浏览产生少量派生缓存应如实记录，不称为新增入库或“零文件变化”。

## 配置、恢复材料和公开证据

解压密码仅可设置、替换或明确清除；打开设置、空输入及保存其他设置保持原值。旧读取接口已退役。环境回退与本地明确清除不同，状态可见，已有密码不可读回。

应用恢复点沿用既有服务：数据库与必要配置/密钥配套，配置缺口必须如实记录。它不是原媒体备份，也不防同盘损坏。最终路径、自动开关、频率和保留规则经用户确认后生效；历史副本、配置和密钥按精确清单确认后处理，不按文件大小或日期机械删除。

受控证据使用匿名标识与合成路径；当前文件脱敏不表示 Git 历史已清理。私人清单、实际路径、恢复点和检查原始日志仅存本机忽略目录。

## 安全边界

生产 Express 响应使用强制 CSP 和适用安全头，保留 Inter 的既有字体来源、blob 媒体和本机 HTTP；不启用 HTTPS 强制升级。独立 Vite 开发 HTML 不因此自动获得 Express 的响应头，不宣称已加强开发文件暴露策略。

PR42阶段的H1四项曾明确暂缓，M5、响应头及错误治理不代表PR42当时已修复H1。后续实现已补充7-Zip启动配置、Host/Origin/代理规则与[开发文件访问边界](/h1-development-boundary)；管理员密码仍沿用“设置 → 安全与访问”的现有开关，不新增强制初始化机制。WAL/NORMAL、云端部署和原媒体备份不因此成为已完成能力。
