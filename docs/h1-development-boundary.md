# Vite 开发监听与文件访问边界

本页只描述客户端开发服务，不改变正式服务的鉴权选择、真实数据路径或原媒体。`vite preview` 只是静态构建预览，不应代替应用后端或作为正式部署入口。

## 监听与代理

- 默认 `DEV_CLIENT_HOST=127.0.0.1`，客户端只监听本机回环地址；静态预览采用相同默认值。
- 需要局域网开发时，由操作者明确将 `DEV_CLIENT_HOST` 设置为本机的指定局域网 IP；也允许显式选择 `0.0.0.0` 或 `::`，但这表示监听全部对应网络接口，不是默认值。
- 值只接受 `localhost` 或 IP 地址，不接受 URL、`true` 或任意主机名。不将 Vite 的 Host 校验设为全放行。
- `DEV_CLIENT_PORT` 保持原有四端口查找规则。`DEV_SERVER_PORT` 指定本机开发后端端口。
- 只有 `/api`、`/thumbnails`、`/previews` 的完整路径前缀代理到 `127.0.0.1` 上的开发后端；例如 `/api-private` 不会因此进入代理。
- LAN 访问还必须符合后端自己的 Host、Origin 和既有鉴权配置。监听地址不是授权策略，也不自动授予远端访问权限；Vite 不伪造可信转发头来绕过后端检查。

这些设置不会自动修改 `.env`、系统 PATH、防火墙或正在运行的服务。切换开发监听范围应由操作者明确执行，避免把带有本机代理能力的开发服务暴露给不可信网络。

## 可以读取与不能读取的内容

开发文件允许范围收窄为 `client` 源码目录和项目的 `node_modules`；依赖 junction/symlink 的真实目标也纳入同一依赖范围，不因此放开整个父工作区。

Vue 源码、正常依赖、public 字体资源、Vite 客户端及 HMR 继续使用。以下内容不能通过 Vite 静态或模块文件入口读取：

- `.mocks`、数据库目录和 SQLite/DB 文件及其 WAL、SHM、journal；
- `.env` 系列、`.git`、`.idea`、`.run`、私有密钥及证书材料；
- 默认恢复目录及实际配置的 `BACKUP_ROOT`；
- 实际配置的 `DATA_ROOT`、`GALLERY_ROOT`、`DB_DIR`、`THUMBNAILS_DIR`、`PREVIEWS_DIR`。

请求层检查覆盖 `@fs`、URL 编码、查询变体、反斜杠、Windows 文件流及 public symlink 目标；Vite 自身仍启用严格文件允许范围与拒绝模式。正常媒体请求必须经既有后端代理，不通过 `@fs` 直接读取图库原件。

API 或媒体代理中的合法相册名可能恰好叫 `private`、`.env` 等。这些请求交给后端处理，不把相册名称误当作客户端私有文件路径。后端仍负责相应资源的访问控制和路径检查。

不要在 public、源码或依赖中保存秘密。此边界不是防御本机已获写权限进程、恶意开发插件、恶意依赖或运行中的符号链接竞态的操作系统沙箱；也不清理 Git 历史中的材料。

## 专项验证

在项目根目录执行：

```sh
pnpm test:dev-security
```

Verify 的 Node22/24 矩阵均执行本专项。它使用临时合成数据库/配置哨兵与随机回环端口，校验静态拒绝、编码变体、private/public symlink、依赖 junction、Vue 源码、字体、真实 HMR WebSocket 和 API/媒体代理。测试结束关闭临时服务并清理自己的夹具，不访问真实数据库或启动 4141/4241。

客户端 jsdom 测试与此 Node 集成套件分开运行；接口成功并不代表已经验证所有浏览器或实际 LAN 部署。正式服务和实际页面的隔离验收仍应按本次候选的受影响范围执行。
