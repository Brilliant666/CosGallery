# 无逐行博主名的 Costuan 目录

## 原因

`completeIdentityDirectory` 曾同时要求编号完整和每行编号前存在博主名。
`NO.001 [DJAWA] Happy Hana Life` 能被作品解析器正确读取，但在身份目录校验中因为编号从位置 0 开始而被拒绝。
此处不是出版社标签或缺少 P/V 声明的问题，也不是范围编号解析回归。

## 限定修复

- 保留默认严格模式：名称变体推断及斜线双名称仍要求逐行身份依据。
- 已有描述前缀、括注双名称分支先验证标题的唯一已登记身份锚点、文章 URL 和唯一标签。
- 只有本篇标签本身唯一命中当前博主规范名或已登记别名，才能允许没有姓名前缀的编号条目。
- 未登记的标题候选、未知标签或历史绑定本身不会开启此选项。
- 若条目实际写有姓名，仍检查全部姓名，包括未知姓名及其他博主冲突；混合目录不会忽略有姓名的行。
- 编号唯一连续、标题声明数量、NO/VOL 一致性及解析有效性仍全部检查。
- 目录未出现姓名时不返回虚构的 `directoryName`。验证消息说明标题/标签身份与编号完整性是两类证据。
- 范围编号通过身份校验不等于能导入或暂存；原范围审核拦截继续有效。

没有新迁移、不登记通用别名、不改变任务、来源、作品或网盘操作。
测试使用内存数据库和合成目录，包括 23 条纯编号示例；不代表已读取或批准当前 SongHana 的完整真实页面。

## 复合标题与混排目录补充修复

PR36 的纯编号合成样例未覆盖页面实际组合，不能代表真实采集通过。
2026-09-20 只读核对公开文章 `https://www.costuan.com/623.html` 后，发现两处遗漏：

1. 标题是 `韩国Song Hana(송하나)`，本篇标签实际为 `Song Hana`。
   括注分支此前只识别 `韩国模特` 前缀，把 `韩国Song Hana` 整体当成首名称，导致真实标签被拒绝。
2. 目录是无姓名、含空格姓名及括注姓名混排。
   `Song Hana 020 [Bimilstory] Vol.02 Micro bikini` 的外层编号优先规则只接受单词姓名，错误选择标题内的 `VOL.02`，与第 002 项发生编号碰撞。

修复保持通用且限定于本篇证据：

- 括注身份校验组合 `韩国`、`韩国模特`、`韩国妹子` 与双名称；规范化只作用于候选，不改原标题或全局别名。
- 剥离前原名、剥离后名字、第二名称及组合形式若已登记给其他博主，仍拒绝。姓名空格沿用既有规范化规则。
- 无姓名行仍要求唯一已登记本篇标签；有姓名行仍逐行校验。不豁免缺号、重复、越界、来源归属或未知名称。
- 外层隐式编号接受 1～8 个横向空白分隔的姓名词项、总长不超过 64、三至四位编号及后续正文。每个词项以字母开头；`NO`/`VOL` 和其编号形态不得作为姓名词项。
- 单号与范围解析共享这一前缀判断。范围仍先检查；已知出版社标题内的 VOL 范围保留既有规则，其余歧义不静默降级。
- 出版社 `Vol.02` 属于标题，保留原文；不会据此生成、合并或覆盖另一个来源作品。

静态公开夹具保留该页 23 行混排结构及声明（不含分享地址或账户数据）。测试覆盖解析、完整目录只读校验、内存库重复导入身份稳定、冲突拒绝，另保留旧例及范围负面回归。
