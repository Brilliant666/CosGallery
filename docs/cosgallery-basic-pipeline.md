# CosGallery 基础全链路

## 阶段结论

截至 2026-08-31，基础模式已完成阶段性验收。它打通了“人工筛选博主 → 采集 Costuan 元数据与资源交付信息 → 只读核对本地图库 → 生成缺失作品任务 → 按博主批量暂存到百度网盘”的链路。

本次账本快照：

- 已暂存缺失作品：111 条
- 涉及博主：9 位
- `pending / claimed / failed`：0 条
- 状态：全部为 `staged`

`staged` 只表示文件已经在 `我的网盘/cos待入库/<博主 ID>` 中核验存在，不表示已经下载、解压或写入 `G:\cos图集`。

## 数据流

```text
HentaiClub 人工筛选 JSON
  └─ 喜欢 / 保留博主 ID、R15 / R18 初始信息
       ↓
CostuanArchiveManager
  └─ 匹配持续更新合集、采集 works[]、记录百度交付目录
       ↓
CosGallery 图库账本
  └─ 与只读 G:\cos图集 按博主和 Costuan 序号核对
       ↓
缺失作品任务
  └─ 生成“Costuan 平台已知但本地未收录”的全部图集
       ↓
CostuanArchiveManager 自动暂存
  └─ 我的网盘/cos待入库/<博主 ID>/<序号>.7z
       ↓
人工下载、改后缀、两次解压、放入本地图库（后续阶段）
```

## 已稳定的基础能力

1. HentaiClub JSON 作为首批人工审美筛选结果导入；它是初始来源，不是永久唯一来源。
2. Costuan 作为第一个资源平台，博主、合集、作品和交付方式分别记录，避免把百度网盘误当作作品来源。
3. `G:\cos图集` 在核对阶段保持只读；程序不会在其中改名、移动、删除或写入文件。
4. 本地作品优先按 Costuan 稳定序号 `NO.xxx` / 三位数字关联；无法确定的目录保留为待核查，不猜测匹配。
5. 缺失任务可重复生成而不重复建单；本地已有部分作品时生成增量任务，本地没有博主目录时生成该博主的全部缺失作品。
6. 扩展按博主领取整批缺失作品，在百度网盘建立或复用独立目录，一次批量复制。
7. 百度长目录采用虚拟滚动也能逐屏选择和核验；任务失败时保留断点并显示博主、阶段和原因。
8. 只有在目标目录实际找到整批文件后，账本才写入 `staged`。

## 状态含义

| 状态 | 含义 |
| --- | --- |
| `pending` | 已生成任务，尚未被扩展领取 |
| `claimed` | 扩展正在处理该任务 |
| `staged` | 已核验存在于百度网盘待入库目录 |
| `downloading` | 浏览器下载方案使用的过渡状态；当前批量暂存模式不以它作为完成条件 |
| `downloaded` | 已下载到本地待入库目录，但尚未完成图库入库 |
| `ingested` | 已解压、核对并纳入本地图库；基础阶段尚未自动实现 |
| `failed` | 自动处理失败，保留错误原因和任务，可继续处理 |

## 当前人工边界

基础模式在百度网盘 `staged` 处结束。以下操作仍由人工完成：

1. 在百度网盘按博主下载 `cos待入库/<博主 ID>` 文件夹。
2. 修正 Costuan 特殊压缩包后缀。
3. 完成两次解压并输入解压密码。
4. 清理 Costuan 的 `.html` / `.txt` 广告文件；图片和视频原文件默认保留。
5. 核对解压结果后放入 `G:\cos图集\<博主 ID>`。
6. 重新运行图库核对，确认缺失作品消失后再进入 `ingested` 设计。

这些步骤尚未自动化，因此不能仅凭 `staged` 删除网盘文件、取消任务记录或认定本地收录完成。

## 下一阶段入口

下一阶段应从“本地待入库处理器”开始，而不是继续扩展百度网页自动化。建议顺序：

1. 扫描 `G:\cos待入库\<博主 ID>`，识别压缩包与对应账本任务。
2. 以可恢复方式完成改后缀、两次解压和密码处理，并生成操作日志。
3. 校验每套作品的图片/视频数量及目标目录，异常项进入待核查。
4. 人工确认后移动到 `G:\cos图集`，再将任务从 `downloaded` 更新为 `ingested`。
5. 重新核对 Costuan，发现后来新增的序号，只生成新的增量任务。

所有删除和覆盖操作必须优先使用回收站或保留可恢复副本。
