# 删除未使用的手工误建博主

此入口不是博主合并，也不是作品清理。仅限 `seed_source=manual` 且已停用的身份。停用仍保留名称冲突保护；不得通过 `confirmDistinct` 将同一个人伪称为两个不同身份。

## 网页及接口

博主库筛选“停用”→管理博主→“删除未使用博主”→检查删除条件→确认删除。预览列出阻断关联；有任何关联时不提供确认删除按钮。删除与停用不同，删除后不能通过“恢复博主”找回，且不会自动添加别名到其他博主。

- `GET /api/admin/archive-catalog/creators/:id/deletion-preview`：只读、一致快照预览。
- `DELETE /api/admin/archive-catalog/creators/:id`：严格接收 `{confirm:true,confirmationToken}`。沿用管理员能力与变更请求保护。
- token 绑定当前身份及别名，不代替授权或引用复核。数据变化／失败后要求重新预览，不自动重试。

## 删除边界与证据

后端在自己的 `BEGIN IMMEDIATE` 写事务内重新检查，随后只移除目标身份、其 `manual` / `manual-history` 别名及纯派生目录记录。若由调用方提供事务，则使用保存点并保留其提交/回滚权；SQLite 锁冲突不会被忽略或转成成功。不重置 ID 自增序列，不移动、回收或读取原件。

检查不区分“活跃/已完成/已撤销”记录；历史引用同样阻断：

| 引用范围 | 检查 |
| --- | --- |
| 直接身份关系 | 从实际 schema 发现指向 creators 的外键，以及规范 `creator_id` / `candidate_creator_id` 等列；来源身份、合集、Work、本地目录、任务、文件观察、来源资料、网页批次和审核均拒绝级联删除或 SET NULL |
| 无外键历史 | 检查业务表全部 `*_json` 列内规范 creatorId/creatorIds、creator 对象、博主名称和既有导入未匹配名称数组；包括原确认计划、决定、恢复、集合确认及嵌套序列化资料 |
| 设置/回执 | `local_ingest.allowlist` 精确规范化名称；`archive.costuan-directory-review.<id>` 键；metadata-check / metadata-task 回执；`managed_creators.migration_000016.conflicts`；其他结构化设置中的规范身份 |
| 正在执行 | 持久接纳/索引锁存在时拒绝删除，不接管、清除或判断其可过期 |
| 自身限制 | 非手工、仍启用、目标目录偏好、非手工来源别名均阻断 |

外部 `source_creator_id` / `sourceCreatorId`、folderId、Work ID 等不当作规范博主 ID。仅同名目录/任意文本标题不作为可靠关系。无法解析的业务 JSON 和关键历史回执保守拒绝：这是“无法证明无引用”，不意味着已证明该条属于目标博主。预览不返回文件清单、设置值或凭据；计数为阻断证据数，可能同一历史行在多类证据中出现，不能当作独立作品总数。

这是低频、明确触发的完整删除审查，不是普通列表查询；会检查历史 JSON，但不扫描图库文件、不解码或计算媒体哈希。新业务若引入不符合现有命名约定的软引用，应同时更新此审查与测试；不能仅依赖删除端的自动外键发现。

## 派生目录与事务

先删除允许的别名和 creator，让既有标脏触发器执行，再删除该 creator 的 `resource_catalog_rows/state`，并递增全库 publication。全部一次提交。旧 Worker 已准备的结果会因 state 不存在而拒绝发布，不会复活已删身份。其他博主的事实和目录状态不变；任一步失败全部回滚。

## 当前交付边界

无新增迁移，不改变来源匹配/入库能力，不提供批量删除或合并。隔离测试覆盖空身份删除、各直接关系与软引用拒绝、预览后独立连接新增引用、权限、回滚、停用名称冲突以及旧 Worker 发布。生产具体身份的删除和保留身份的别名添加必须在后续明确执行范围中处理，本开发不执行这些动作。
