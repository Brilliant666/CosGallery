# 术语、交互恢复与定向性能优化

本轮基于 PR52 的 `7f380613`，按用户确认的三个优先阶段实施。实现和隔离验证不表示已部署；真实 4141、现有博主标签、业务数据和配置不属于本轮写入范围。

## 对象与术语

- 规范博主、独立作品 Work、本地副本、照片／视频和物理目录分别表达，不能仅替换名称制造身份归并。
- 搜索当前仍查询媒体及图库目录，目录结果尚不是规范博主结果，媒体数量也不等于独立作品数量。界面按实际返回对象命名。
- 回收站总标题涵盖作品与媒体；单张回收、整作品回收和历史回收记录的范围仍由各自确认内容说明。
- 入库已知状态使用中文；原始阶段、错误和文件动作保留在技术详情。登记处置意图不表示文件已经处理完成。
- 真实文件管理的目录、主副本、原件及路径保留。未改变入库决策、文件处置或恢复流程。

## 交互恢复

- 图库请求失败提供当前条件的明确重试，失败不伪装成无结果。
- 搜索输入拥有稳定、独立的辅助功能名称；清除按钮不再成为输入的名称。媒体搜索失败可重试失败页，保留此前结果和查询条件。
- 收藏操作错误就近显示，恢复按钮可用状态；不把单项操作错误替代整个列表，也不因失败回滚再次触发同一存储写错误。
- 默认收藏和自定义合集均区分“写入失败”与“已写入、列表刷新失败”；已成功状态不反向回滚。归属待核实时，下一次合集变更先重新读取；同一媒体的收藏操作串行，其他媒体独立操作。
- 通用确认、作品回收与合集操作补充初始焦点、Tab 约束、Esc 关闭及返回原入口。提交期间不关闭确认；多个确认界面仅由最上层约束焦点，输入法的 Esc 不误关弹窗。

## 性能范围

仅针对首页离屏图集照片的预览请求和博主列表封面详情补全开销验证。照片继续使用现有缓存预览 URL，视频继续原件优先、按需兼容，分页及缓存语义保持。

规范博主的全范围身份归并、排序、别名匹配和统计必须先保持正确。本轮不以直接给物理目录查询添加 LIMIT 的方式改变规范博主分页，也不把本机接口的少量耗时样本当作首屏、滚动或全站性能结论。

隔离合成库含 200 位规范博主、202 个目录与 202 条媒体。10 种查询覆盖分页、越界、别名、分级、停用、未关联、空搜索、标签覆盖分级及管理员偏好：前后完整响应一致。首 24 项的封面详情读取由 201 次降至 24 次，空页由 201 次降至 0 次，别名单结果由 201 次降至 1 次。20 次热样本中位数约 24.27→12.70ms，仅描述该合成数据下的服务调用；不是正式图库 API、首屏或滚动性能结论。

1440×900 Chromium 使用实际 production 前端入口和 24 张合成图集卡，初始唯一照片预览请求从 24 个降至 5 个；首图与滚动至末项后的图片均正常加载。原生 lazy 会预取近邻，并非严格只请求屏内图片。该测试没有测量真实媒体带宽、LCP 或用户首屏速度，不代表所有图集的节省比例。

## 后续边界

- 搜索若要直接以规范博主／独立作品为结果，需要另行调整搜索契约；本轮只纠正当前对象的名称。
- 物理目录资料、设置中明确的文件夹模式、未路由旧页面及技术详情不机械更名。此轮不是删除兼容代码的授权。
- 完整 SQL 分页仍待研究，不能牺牲多目录身份归并、全局统计和当前排序以减少构造量。
- 收藏的同媒体写操作已串行；先前悬停触发的独立只读归属请求若乱序返回，仍需另行研究读请求版本保护。本轮未宣称解决全部并发状态问题。
- 保留的少量本机接口时长不能用于判断滚动瓶颈；将来若研究首屏，需要固定设备、视口、网络、缓存和目标元素测量。
- 无可用消息的 HTTP 错误仍可能落入英文通用兜底；本轮没有批量改写后端原始错误，也不宣称所有异常文案已经中文化。
