# 安装与启动

当前推荐使用 **CosGallery 源码 + 本机 Node.js + pnpm**。本机后端直接读取配置的本地目录；浏览器不需要上传整套媒体。IDE 可以作为启动工具，但不是必装依赖。

## 准备运行环境

| 项目 | 当前要求与验证范围 |
| --- | --- |
| Git | 用于取得本仓库及记录版本。 |
| Node.js | 推荐 Node 24.21.0，由 `.node-version` / `.nvmrc` 固定。仓库使用 `node:sqlite`；GitHub Verify 同时验证 Node 22 和 24。根 `package.json` 的 `engines` 声明支持 `>=22.16.0 <23` 或 `>=24.0.0 <25`，不承诺其他版本可用。 |
| pnpm | 使用根 `package.json` 指定的 `10.28.0`，依赖由 `pnpm-lock.yaml` 锁定。本文不将 npm 安装视为等价验证路径。 |
| FFmpeg / FFprobe | 视频元数据、缩略图、预览及动画 AVIF 处理需要；通过 PATH 或配置中的完整路径提供。 |
| 7-Zip | Costuan 压缩包入库需要，在本机启动配置中设置 `LOCAL_INGEST_SEVEN_ZIP_PATH` 绝对路径，网页只读显示并验证。已解压图集的本地入库不需要先重新压缩。 |
| 本地存储 | 数据库、图库及派生目录需有适当权限和空间；入库会移动所选目录，不能把图库仅挂为只读再期待完成入库。 |

安装 Node 后确认 `node --version`。安装或启用 pnpm 10.28.0 后确认 `pnpm --version`；若已使用统一的本机工具管理方式，沿用它，不必为了本文另装一套。

## 从源码运行

以下为 Windows PowerShell 示例，工作目录是新克隆的仓库根目录：

```powershell
git clone https://github.com/Brilliant666/CosGallery.git
cd CosGallery
pnpm install --frozen-lockfile
Copy-Item .env.example .env
```

`Copy-Item` 仅用于第一次创建配置；已有 `.env` 时保留原配置，不覆盖。启动前打开 `.env`，按[配置说明](/configuration)设置实际路径。保留 `COS_GALLERY_MODE=1`，以使用本指南描述的博主与作品图库模式。

如果先准备环境、之后再手工选择 Costuan 待入库范围，可设：

```dotenv
LOCAL_INGEST_STARTUP_SCAN=false
```

这只关闭 Stage3 的启动等待区补偿扫描，不是关闭数据库迁移、完整校验或资源目录 Worker。全新的空索引仍可能触发首次图库扫描，因此第一次启动前应确认 `GALLERY_ROOT` 指向预期图库，而不是混乱的下载等待区。

以下是配套构建入口。用于正式实例前，先确认目标版本的精确 Head 已通过 Verify，并按[最小部署检查](/governance-runtime#分级验证与最小部署检查)准备所需恢复材料和切换步骤；构建成功本身不代替候选验证。已有适用的构建产物可直接复用。

```powershell
pnpm build
```

`pnpm build` 编译配套的 `server/dist` 和 `client/dist`，不构建文档站。需要启动且当前授权已覆盖时，再执行 production 启动入口；只要求安装并保持关闭时，完成下文的离线验收后交接。

```powershell
pnpm start
```

`pnpm start` 使用 production 模式：服务端工作区先执行迁移入口，再启动编译后的服务；数据库连接初始化也保留迁移检查和完整性校验。不要为了日常启动再手工额外运行一次迁移命令。

默认访问 [http://127.0.0.1:4141](http://127.0.0.1:4141)，健康接口为 `GET /api/health`。实际端口由 `SERVER_PORT` 决定，默认只监听 `127.0.0.1`。迁移或完整性检查期间尚未就绪是正常启动阶段，不承诺固定秒数。

首次运行后，按[快速开始](/quick-start)选择本地入库或 Costuan 路径。空图库没有作品不等于安装失败；没有配置访问保护时，可访问服务的人能直接使用管理功能。开放局域网或反向代理前先阅读[安全说明](/security)。

## 目录与平台边界

推荐将数据库、正式图库、已解压等待区、压缩包等待区及处理区分开。示例结构见[配置说明](/configuration)，盘符与文件夹名称不是项目硬编码要求。

- 本地目录接纳使用受检查的同卷移动；Costuan 的图库、压缩包等待区、处理中目录也有同卷及不重叠约束。
- Windows 回收站适配器用于相应广告、空父目录及压缩包清理；其他系统上该适配器明确报不可用，不是自动永久删除的替代实现。
- 不支持把链接、junction 或任意外部路径当作已经批准的导入范围。
- 远程访问网页不会让远程服务器获得你电脑的盘符。服务运行在哪台机器，目录选择与执行就发生在哪台机器。
- 7-Zip没有默认程序路径，不从PATH搜索。先在本机配置自己的可信原生程序，再启动服务；网页环境工具仅验证当前配置。

Windows 本机路径是当前重点验证环境。Linux、NAS、云端或网络共享的浏览能力，不能代替 Windows 入库/回收闭环兼容性验证。

## 升级现有实例

先核对目标候选的精确 Head Verify、实际运行来源、业务空闲状态及适用恢复材料，保留原始媒体和配置；已有恢复点可用时不机械重复备份。本地加密解压密码还依赖独立 key 文件，见[密码配置](/local-ingest-password-settings)。不要把一份旧数据库恢复到已有新入库事实的目录上来“清理状态”。

准备新版本的配套前端、后端和维护 CLI，优先复用已验证产物。确需替换时，先只读核对实际进程与业务状态；需要停止时精确停止并确认退出，再安装配套产物。不要在旧后端仍运行时先覆盖新前端，也不要让新 CLI 指向另一版本的数据库结构。仅文档或 Squash 身份变化且应用构建输入等价时，可按[运行时治理](/governance-runtime#_4141-最小部署闭环)复用既有进程与产物，如实记录实际版本。

安装、启动和运行验收分别记录；用户一次授权已覆盖多个阶段时，直接继续完成，不逐步重复询问。

- **仅安装、保持关闭：** 离线核对前后端与 CLI 构建身份、配套文件及本次保护项，确认保持关闭，记录“安装完成、未启动、运行验收待用户启动”。不为安装验收调用应用启动、迁移或 HTTP 接口。历史部署 profile 可能绑定旧版本和路径，不能直接重放。
- **授权包含启动与运行验收：** 安装完成后再分别执行启动、健康检查和必要的受影响范围核查；HTTP 检查与进程启停分开执行。由用户自行启动时，之后只读核对当前进程、实际版本和健康状态，不为核查重复启停。

正常启动按序应用待执行迁移，具体版本以目标候选的 `server/db/migrations/` 为准。已应用版本不应反复升级或执行 down，不能删除迁移记录绕过异常。发生失败时保留真实错误与恢复材料，见[故障处理](/troubleshooting)。

## Docker 与上游参考

仓库保留 `Dockerfile`、`docker-compose.yml` 和 `docker-compose.local.yml`。其中默认 Compose 使用 `ghcr.io/foldergram/foldergram:latest`，是 **Foldergram 上游镜像**，不能用它代表当前 CosGallery 功能。

原 GHCR tag 自动发布已暂停，容器工作流仅支持手工构建检查，不推送镜像。现存 Docker/Compose 属于上游遗留链路，可供开发者研究，**不作为已验收的 CosGallery 部署方式**，也不代表 Windows 入库、7-Zip、回收站或本地密码恢复闭环已经验证。发行与部署边界见[运行时治理](/governance-runtime#最小检查与发行边界)。

## 开发与文档站

需要热更新或修改代码时见[开发说明](/development)，不要把开发端口与 production 的 4141 混用。文档站单独构建：

```powershell
pnpm build:docs
```

输出为 `docs/.vitepress/dist`，不需要为文档构建启动图库服务。
